## 1. 引言 / Introduction

### 1.1 研究背景

教师批改一份作业，真正耗时的不是客观题，而是主观题：要看学生的解题步骤、判断每一步对错、按得分点给分、还要写批注。这项工作量大、标准难统一，且反馈往往要等好几天。

近年来大语言模型能读题能作答，于是很自然会想到"让模型来批改"。但直接用一个云端大模型去批全卷，会遇到三个问题：**贵**（每一题都要联网调用）、**慢**（逐题等待）、**不稳定**（同一题两次问可能给两个不同的分）。

### 1.2 问题陈述

本研究要回答的核心问题只有一个：

> **能不能让批改既准确、又便宜、还稳定？**

我们把它拆成三个可测的子问题：

1. 一个小模型能不能在普通显卡上把批改做到可用水平？（对应"便宜"）
2. 什么时候该信任小模型，什么时候该请大模型帮忙？（对应"准确"）
3. 两者的意见不一致时，怎么合成最终分数？（对应"稳定"）

### 1.3 本文的做法

我们训练了一个**本地小模型**做一线批改，它同时输出答案与把握度；只有当把握度不足时，才把题目**送云端大模型**复核；最后按固定权重把两方意见**合成**最终档位。

全卷 2,394 道题目的实测结果是：整体准确率 **73.48%**，主观题打分误差 **1.2110 档**；接入云端复核后，打分误差进一步降到 **0.9425 档（−22.2%）**，而每份作业的云端调用成本仅约 **0.80 元**。

## 2. 前期调研 / Essential Research

### 2.1 现有批改方式与其局限

| 方式        | 优点     | 局限                  |
| --------- | ------ | ------------------- |
| 人工批改      | 准确、有温度 | 慢、标准因人而异、反馈延迟       |
| 规则/关键字匹配  | 快、零成本  | 只能判客观题，无法处理主观题的多种解法 |
| 云端大模型直接批改 | 能读主观题  | 贵、慢、同题两次结果可能不同      |

### 2.2 云端大模型直接批改的问题（实测）

我们实测了"把全卷 365 道主观题全部交给云端大模型批改"，结果它不是帮忙，而是**帮倒忙**：

| 指标            | 本地小模型  | 全部交云端        | 变化           |
| ------------- | ------ | ------------ | ------------ |
| 打分 MAE        | 1.2110 | **1.2192**   | 变差           |
| 档位完全命中率       | 54.25% | **41.10%**   | 掉 13.15 个百分点 |
| 被改好的题 / 被改坏的题 | —      | **91 / 114** | 改坏的更多        |

**结论：云端模型对本地已经判对的题，是净破坏。** 这直接否掉了"全部交给大模型"这条最直觉的路。

> 数据来源：`logs/s2_analysis_all365_final.json`（365 道全量送云端实测）

### 2.3 小模型直接批改的问题（实测）

小模型的短板集中在**打分**这一类：

| 题型           | 准确率    | 宏平均 F1     | 落差           | 样本量   |
| ------------ | ------ | ---------- | ------------ | ----- |
| 判断 noul      | 85.88% | 0.8587     | **0.01 pp**  | 1,296 |
| 找错因 choice   | 61.12% | 0.5034     | 10.78 pp     | 733   |
| **打分 score** | 54.25% | **0.2831** | **25.94 pp** | 365   |

准确率高而宏平均 F1 低，说明它是靠"押多数档"拿到 54% 的——**10 个档位里有相当一部分它从来没判中过**。

另一个问题更隐蔽：**它有 97.99% 的判断题把握度恰好是 1.000**（1,296 道里 1,270 道），可这些题里它会判错。把握度对它完全没有区分度，闸门等于虚设。

> 数据来源：`eval/r2_e2w_val_b1.json`、`logs/gateway_val_b1_details_logits_2026-10-17.jsonl`

## 3. 创新方案 / Innovation Design

### 3.1 总体架构

四步：

1. 教师上传试卷与评分标准，学生上传作答；
2. **System1（本地 322M）** 逐题给出答案与把握度；
3. **题型差异化闸门** 决定哪些题需要送云端；
4. **System2（云端 M3）** 只复核这些题，结果与本地意见**门控混合**后输出。

> **图 1：双 System 批改系统的总体架构**（见 `图表/Fig01_系统总架构.svg`）

### 3.2 System1：本地小模型的三个原语

我们没有让模型"生成文字答案"，而是让它做三件判别式的选择——这是整套方案的第一个关键决定：

| 原语         | 任务         | 输出         |
| ---------- | ---------- | ---------- |
| 判断 noul    | 逐步看学生的每一步  | 对 / 错（二选一） |
| 找错因 choice | 从若干原因中挑出错因 | 若干个中选一个    |
| 打分 score   | 给主观题定档     | 0~9 共十档    |

**为什么这样做很重要**：判别式输出不会"编造内容"。模型只是在固定候选里挑一个，因此它天然不会像生成式模型那样胡编一句评语。这是我们对"批改"这种要负责任的场景的刻意选择。

底座为开源的 ModernBERT 编码器（22 层 / 隐层 768 / 3.22 亿参数），我们在此基础上做**二次微调**——即是给一个已经受过良好教育的底座做岗前培训，而不是从零训练一个模型。

> **图 2：底座 ModernBERT 的混合注意力架构**（见 `图表/Fig02_底座混合注意力架构.svg`）
>
> 顺带说明一个容易被误解的点：这个底座本身就采用"每 3 层全局注意力 + 其余层滑窗局部注意力"的混合注意力结构。这是底座自带的结构，不是我们新增的。

### 3.3 闸门：不同题型用不同的尺子

这是本方案的第二个关键决定。

按常规做法，闸门直接用把握度：`把握度 ≥ 0.85 就相信它`。但我们实测发现**同一把尺子对不同题型的效果天差地别**：

| 题型          | 把握度能否区分对错                                   |
| ----------- | ------------------------------------------- |
| 找错因 choice  | 可以                                          |
| 打分 score    | 可以（高把握段 MAE 0.6385 vs 低把握段 2.0132，差 3.15 倍） |
| **判断 noul** | **完全不能**（97.99% 的题把握度都是 1.000，一条水平线）        |

于是我们换了一把尺子：**logit 间隔**——模型给第一名候选的打分与给第二名的打分之差。

这把尺子的好处是**与温度无关**：它直接读候选之间的差距，不受"把分数压平还是压尖"的后期处理影响。换尺子之后，判断题的区分能力立刻恢复：

| 题型         | 取间隔最大的前 10% 的准确率 | 全体准确率  |
| ---------- | ---------------- | ------ |
| 判断 noul    | **100.00%**      | 85.88% |
| 找错因 choice | 95.89%           | 61.12% |
| 打分 score   | 97.22%           | 54.25% |

**信息其实一直都在，只是被压成了 1.000 而看不见；换把尺子就恢复了。**

> **图 12：按 logit 间隔排序后的选择性准确率**（见 `图表/Fig12_logit间隔选择性准确率.svg`）

### 3.4 一个必须说清的关口：题级与记录级不是一回事

在设计闸门时，我们踩到一个反直觉的坑。

按"题"看，τ=0.85 时能自动放行 **77.99%** 的题目，这些题的准确率 **84.20%**，看起来很好。

但按"整份作业"看——要求这份作业里每一题都过闸门才算自动通过——就只剩 **34.25%** 了。

原因是数学的：一份作业平均有 6.6 道题，每道题独立过闸的概率约 0.78，全部过闸就是 0.78⁶·⁶ ≈ 0.34。

> **图 9：闸门阈值 τ 对自动批改覆盖率与准确率的影响**（见 `图表/Fig09_闸门阈值扫描.svg`）

**这两个口径一定要分开写**，否则会误导读者。

### 3.5 System2：云端按需复核与门控混合

只有低把握度的打分题才会送云端（每卷 152 道，占 41.6%）。云端给出自己的档位后，按固定权重合成：

```
最终档位 = clip( round( 0.45 × 本地期望档位 + 0.75 × 云端档位 − 0.25 ), 0, 9 )
```

高把握的 213 道**完全不动**——这正是 2.2 节那条实测教训的应用。

**为什么是加权合成而不是二选一**：我们实测过纯"二选一"的选择器，折外 MAE 只到 1.028~1.054，未过显著性门槛；而加权合成能到 0.9425。

### 3.6 异常处理与人工复核

| 异常情况               | 处置                       |
| ------------------ | ------------------------ |
| 云端调用失败（HTTP 或解析失败） | 回退到本地判定，**绝不因为失败就给 0 分** |
| 上传格式不合格            | 整份拒绝并提示，不做部分批改           |
| 两方分歧过大             | 转入人工复核队列                 |
| 任何一道记录级把握度不足       | 整份作业转人工复核                |

实测中 152 道送云端的题有 9 道失败了（失败率 5.9%），全部按上表回退——这也正是实测值 0.9425 与理想上限 0.9030 之间差距的来源。**对外报数时用 0.9425，并注明失败率。**

## 4. 成果分析 / Verification Analysis

### 4.1 实验设置

| 项    | 内容                                            |
| ---- | --------------------------------------------- |
| 主评测卷 | val_b1，365 条记录 / 2,394 题，全部来自 SAS-Bench 公开数据集 |
| 对照卷  | val_tal（459 条 / 2,337 题，TAL-SCQ5K 来源，无打分题）    |
| 封存卷  | 367 条 / 2,402 题，**全程不参与训练、验证与任何评估**           |
| 训练数据 | 6,537 条记录 / 37,066 题                          |
| 硬件   | 单张 RTX 4050 笔记本显卡（6 GiB 显存）                   |
| 显著性  | n=365 时，MAE 的 1σ ≈ 0.099 档；1σ ≈ 2.6 个百分点      |

> 数据来源：`workspace/data/` 实测统计；`eval/` 各卷评估报告

### 4.2 微调带来了什么

| 版本                      | 整体         | 找错因    | 打分     | 判断     | 打分 MAE     |
| ----------------------- | ---------- | ------ | ------ | ------ | ---------- |
| **零样本底座（未微调）**          | 38.64%     | 21.69% | 23.56% | 52.47% | **3.8877** |
| 第 1 轮微调                 | 71.64%     | 58.66% | 52.05% | 84.49% | 1.4274     |
| 第 1 轮 + 题型加权            | 72.22%     | 60.44% | 53.15% | 84.26% | 1.3041     |
| **第 2 轮（= EduJev 1.1）** | **73.48%** | 61.12% | 54.25% | 85.88% | **1.2110** |

整体准确率 **+34.84 个百分点**，打分误差 **−68.8%**。

零样本时打分的宏平均 F1 只有 **0.0924**（十档几乎乱猜），微调后升到 **0.2831**。

> **图 3：微调过程的三题型准确率与打分误差演进**（见 `图表/Fig03_训练演进与零样本基线.svg`）

**这里有一条方法论发现值得单独说明**：

- 从"第 1 轮"到"第 1 轮加权"，整体涨 0.58 个百分点，但**判断题反而掉了 0.23 个百分点**——这是零和的，是从强项身上割肉；
- 从"第 1 轮加权"到"第 2 轮"，整体涨 1.26 个百分点，**三个题型全都涨**——这是无损的，因为加的是数据而不是调权重。

**所以：加数据优于调权重。**

### 4.3 打分误差集中在少数题上

| 误差档   | 占样本        | 累积贡献的总误差   |
| ----- | ---------- | ---------- |
| ≥ 3 档 | **16.99%** | **67.19%** |
| ≥ 5 档 | **7.40%**  | **39.37%** |

**少数几道大错，贡献了大部分总误差。** 这决定了改进方向：要治的是"尾巴"，不是全体。

> **图 5：打分误差的分布与其对总误差的贡献**（见 `图表/Fig05_打分误差贡献.svg`）

### 4.4 双 System 协同的效果

| 路径                      | 打分 MAE     | 相对基线          |
| ----------------------- | ---------- | ------------- |
| 本地小模型直接判定（基线）           | 1.2110     | —             |
| 改用序数期望 E[档位]            | 1.1616     | −4.1%         |
| 云端大模型单独批改               | 1.1479     | −5.2%         |
| 全部交给云端复核                | 1.2192     | **+0.7%（更差）** |
| **门控混合（本系统，真实 API 实测）** | **0.9425** | **−22.2%**    |
| 理论上限（假设云端 100% 可用）      | 0.9030     | −25.4%        |

同时，档位完全命中率 54.25% → **57.26%**，误差 ±1 档以内比例 72.05% → **76.99%**，低把握段的误差从 2.0132 降到 **1.3684**。

> **图 6：五条提升打分准确度的路径实测对比**（见 `图表/Fig06_提升路径对照.svg`）

**为什么门控混合能成**——看按错误大小分层后的对比就明白了：

| 本地模型的误差 | 题数  | 本地误差       | 云端误差       | 谁更准              |
| ------- | --- | ---------- | ---------- | ---------------- |
| 0（已判对）  | 198 | 0.0000     | 0.6717     | 本地               |
| 1       | 65  | 1.0000     | 1.4462     | 本地               |
| 2       | 40  | 2.0000     | 1.3000     | 云端               |
| 3~4     | 35  | 3.5143     | 2.3714     | 云端               |
| **≥ 5** | 27  | **6.4444** | **2.1111** | **云端（强 4.33 档）** |

**云端模型是"专治大病"的，不是"全科医生"。** 它只在本地错得离谱时才明显更强，这恰好就是"高把握题绝不送云端"这条规则的由来——把两者放在一起，才能各取所长。

> **图 7：云端模型与本地模型在不同错题难度上的表现**（见 `图表/Fig07_云端与本地按误差分层.svg`）

## 5. 讨论结论 / Discussion and Conclusion

### 5.1 讨论：三条被实测纠正的直觉

| 直觉                   | 实测结果                                            |
| -------------------- | ----------------------------------------------- |
| "大模型更强，全部交给它批最好"     | 全部交给云端反而更差（1.2110 → 1.2192），改坏的题比改好的多           |
| "模型说把握度 99%，那它八成是对的" | 判断题有 97.99% 把握度是 1.000，它照样判错；把握度对它没有区分度         |
| "多问几次取多数票会更稳"        | 同一题问三轮，只有 35% 的次数三轮一致；多数票 1.6833 还不如最好单次 1.5333 |

**由此得到的一般性原则**：分工的依据不是"谁更强"，而是"谁在哪种题上更强"。本地小模型与云端大模型各有各的擅长区间，把它们放在各自擅长的区间里，整体才优于任何单独一方。

### 5.2 结论

1. 一个 322M 的本地模型，在 6 GiB 显存的普通笔记本显卡上，可以把作业批改做到整体准确率 73.48%、28.888 题/秒；
2. 用**题型差异化闸门**（打分/找错因用把握度，判断用 logit 间隔）决定何时请外援，是让这套分工成立的关键；
3. 用**门控混合**合成两方意见后，主观题打分误差从 1.2110 降到 0.9425（−22.2%），每份作业成本约 0.80 元；
4. 少数大误差题贡献了大部分总误差（16.99% 的题贡献 67.19%），下一步改进应集中在这里。

### 5.3 局限与下一步

| 局限                                    | 下一步            |
| ------------------------------------- | -------------- |
| 打分题只占训练数据 7.3%，是能力短板（宏平均 F1 仅 0.2831） | 补充中文主观题评分数据    |
| 主卷与训练集同为 SAS-Bench 来源                 | 在完全独立的卷上复核     |
| 未与真人教师批改做对照                           | 需采集教师批改结果作为金标准 |
| 云端调用仍有 5.9% 失败率                       | 增加重试与本地兜底策略    |
| 数据量—效果曲线未测                            | 需多次训练，成本较高     |
